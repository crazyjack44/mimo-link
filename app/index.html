同步与路由

two-step
就绪
1发现 MiMo Desktop 进程
2定位实时能力端口
3校验 / 重签 Token
4点「路由」才写入目标（不会自动）
常用值：mimo-desktop/mimo-pro、mimo-desktop/mimo-v2.6-pro
必须先生成统一 scoped token 该 token 由 mimo llm-server issue 签发，是本机唯一根凭据。 其他电脑不会自动带上同一 token；未生成前，下方 mlk_ API Key 无法正常分发 / 转发到 MiMo。
写入插件目录 mimo-link.env · 每台机器需各自生成
路由 / 导出时写入配置文件（Codex auth.json、Hermes .env、CC Switch api_key）。mlk_ Key 走 :8765 桥接并计量；留空则使用引擎 Token。
Hermes：路由时写入 model_aliases.mimo-desktop · Codex：合并写入 ~/.codex，经 :8765 桥接
两步流程（启动 / 同步都不会自动改配置） ① 只发现端口与 Token，不写 Hermes / Codex；② 点「路由」才落盘。 Codex 使用本地桥接 :8765（wire_api=responses），需保持本应用运行。 也可导出 CC Switch 配置手动导入。

关于 mimo-link

将 Xiaomi MiMo Desktop 的本地能力 API 接到 Hermes 或 Codex。 Desktop 端口随会话漂移；应用启动与「同步端点」都只做探测，不会自动改配置—— 必须点击「路由」才会写入目标。Hermes 写入 mimo-desktop 别名； Codex 写入 ~/.codex（wire_api=responses，经 http://127.0.0.1:8765/v1 桥接到 MiMo chat.completions， 需保持本应用运行）。Token 界面只显示掩码，复制时才取完整值。
